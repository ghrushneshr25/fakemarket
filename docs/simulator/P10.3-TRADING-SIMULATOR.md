# P10.3 — Trading Simulator

## Status

**IMPLEMENTED** (CTO re-review pending — addresses REQUEST CHANGES)

## Purpose

Production-style **demonstration workload** that drives the **real** exchange path so
P10.2 dashboards show live commands/trades/WAL/latency.

| | P7 | P10.3 |
|--|----|-------|
| Owner | Formal benchmarks | Demo / operator traffic |
| Path | Controlled benches | gRPC → Service → match → WAL |
| Claims | Throughput/latency science | Observed demo rates only |

## Architecture / transport boundary (Q1)

```
fakemarket-sim
    → gRPC TradingService over **bufconn** (in-process transport)
    → grpcapi.TradingServer
    → trading.Service
    → Router / Workers / AuthorityGate (if set)
    → Risk / Matching
    → Financial WAL (authoritative)
    → post-durable LivePublisher (derived MD)
         → md.Trade / BookDelta / BestQuote
         → Hub.Publish → fakemarket_marketdata_* metrics
    → metrics.Registry (existing fakemarket_* only)
```

MD is **derived** after durable commit (not manufactured by the simulator). No WS client required for metrics.

**Compose path:**

```
docker compose
  node-a|b|c     → HTTP packaging (P10.1 health/metrics; no trading gRPC yet)
  sim            → embeds full trading stack + exposes :9100 /metrics
  prometheus     → scrapes nodes + sim:9100
  grafana        → P10.2 dashboards
```

**Why bufconn still satisfies P10.3:** the production gRPC adapter and full Service→match→WAL
path are exercised. Compose nodes are the packaged HTTP process; the **sim service** is the
workload generator that also hosts the exchange metrics registry for live scrape. TCP gRPC to
Compose nodes is out of scope until main wires TradingService (not required to close P10.3).

**Forbidden:** direct book/WAL/trade/metric mutation. **Sim does not emit** `fakemarket_*` (Q14).

## CLI

```bash
# Canonical demo (2 minutes, 4 clients, 8 instruments)
go run ./cmd/fakemarket-sim \
  -seed 42 -scenario normal -duration 2m -rate 50 \
  -clients 4 -instruments 8 -accounts 50 \
  -metrics-addr :9100

make sim          # same
make sim-quick    # short check
```

### Flags

| Flag | Default | Meaning |
|------|---------|---------|
| `-seed` | 42 | Deterministic RNG |
| `-scenario` | normal | quiet \| normal \| active \| replay |
| `-duration` | 2m | Used if `-commands` = 0 |
| `-commands` | 0 | Hard stop after N cmds |
| `-rate` | 50 | Target cmds/sec (paced) |
| `-clients` | 4 | Concurrent gRPC workers (runtime only) |
| `-instruments` | 8 | SIM-* universe |
| `-accounts` | 50 | SIM-ACCOUNT-NNNN |
| `-cancel-rate` | scenario | Cancel probability |
| `-market-rate` | scenario | Market fraction of new orders |
| `-aggressive-rate` | scenario | Crossing limit fraction |
| `-wal` | temp unique | WAL directory |
| `-metrics-addr` | off | Serve exchange `/metrics` `/health` `/ready` |

## Resolved configuration example (normal)

```text
Seed:                 42
Scenario:             normal
Duration:             2m0s
Rate:                 50.0 cmd/s
Clients:              4
Accounts:             50
Instruments:          8
Order distribution:
  CANCEL rate:        15% (when live sim-owned orders exist)
  MARKET rate:        15% of new orders
  LIMIT rate:         85% of new orders
  PASSIVE LIMIT:      65% of limits
  AGGRESSIVE LIMIT:   35% of limits
Quantity range:       1..10
Price range:          ref±1..8 (passive) / ref±1..5 (aggressive); ref=100+7×instIdx
```

### Why these probabilities (Q6)

- **15% cancel** — enough cancel lifecycle without emptying the book  
- **15% market** — forces crossing against resting liquidity  
- **35% aggressive limits** — guaranteed trade pressure via ref± pricing  
- Passive majority builds book depth for later crosses  

### Trade generation (Q7)

Aggressive limits price through the reference; markets take liquidity; sellers are the
second half of accounts with pre-loaded inventory so sells can rest/fill.

## Determinism (Q5, Q11)

- xorshift64* from seed; `GenerateStream` builds the full list **before** execution  
- Fingerprint = FNV-64a over generation config + stream (excludes clients/WAL/metrics)  
- Concurrent clients **do not** change the generated stream or fingerprint  
- Same seed+config → identical command contents (tested)

## Authoritative trades (Q2, Q3, Q15)

After shutdown, sim runs `recovery.RecoverDir` + `invariants.VerifyStateWithBaseline`:

| Counter | Source |
|---------|--------|
| Commands generated | stream length |
| Commands submitted | gRPC attempts |
| Accepted / rejected | RPC success / error |
| Orders cancelled | successful CancelOrder |
| Fill-like responses | submit status FILLED\|PARTIAL (non-authoritative) |
| **TradesExecuted** | recovered `State.Trades` |
| **Executions** | recovered `State.Executions` |
| **Trade.Sequence max** | max `Trade.Sequence` |
| **Event.Sequence** | recovered last event seq |
| PartialFills | recovered order status |

Partial-fill example is printed from recovered order remaining/filled quantities.

## P8.6 (Q4)

Uses the **existing** recovery oracle + `VerifyStateWithBaseline` (structural + conservation).
No simulator-specific invariant engine.

Journal fix (resting-side reservation release steps) ensures recovery matches live capacity
so the oracle can consume sim WALs.

```text
P8.6: PASS
Violations: 0
```

## Accounts (Q9)

Seeded via `domain.NewAccount` + `AddToPosition` for seller half (same pattern as P8.6 tests).
No bypass of risk/reserve/match/settle on the trading path.

## Cancels (Q8)

Cancel targets are **sim-owned** slots from the generated stream (live order index created by
this sim). Cancel uses the original command's `AccountID`. Never invents foreign order IDs.
Failed cancel (already filled) → rejected counter, **no retry**.

## Ambiguous submit (Q10)

**No retry** on lost/failed RPC response. Aligns with P6 ambiguous-submit contract.

## Observability (Q12–Q14)

Sim starts optional HTTP on `-metrics-addr` serving the **exchange** registry.
Before/after sample printed for:

- orders submitted/accepted/rejected/cancelled  
- trades_total  
- wal_appends / wal_bytes  
- trading_command_duration_seconds_count  
- grpc_server_rpc_duration_seconds_count  
- marketdata_events_total / publish_duration (live publisher on every durable submit/cancel)

Compose: Prometheus job `fakemarket-sim` scrapes `sim:9100`.

## Graceful stop

SIGINT/SIGTERM → stop enqueue → drain workers → shutdown WAL → P8.6 oracle → summary.

## P10.4 boundary

Failure injection demos remain **P10.4**. P10.3 is healthy traffic only.
