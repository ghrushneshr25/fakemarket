## 25. Interview / Architecture Defensibility (brief)

1. **WAL SoT** — only durable accepted history; memory is cache.  
2. **Single-writer** — per-instrument lock avoids concurrent book races.  
3. **Determinism** — ordered commands + pure match; replay tests.  
4. **Duplicates** — EventID / idempotency keys.  
5. **fsync fail** — Append errors; fail-closed; no success.  
6. **Crash after commit** — durable; recovery replays; client may need idempotent retry.  
7. **Recovery deterministic** — fold events in seq order.  
8. **Resting orders** — recovery books → LoadBookFrom before Ready.  
9. **Stale fence** — AuthorityGate + SharedAuthority/fence map.  
10. **Consensus vs WAL** — consensus chooses writer; WAL is financial log.  
11. **MD derived** — public projection; not ledger.  
12. **Partition** — minority no elect; majority one writer.  
13. **Reservations** — capacity before match; journaled.  
14. **Bottleneck** — WAL fsync / executor_wait under contention (P7).  
15. **Bug** — resting reservation journal gap (fixed).  
16. **Before real prod** — TLS/auth, full process packaging, ops runbooks.  
17. **Keep** — WAL SoT, single-writer match, fence-before-write.  
18. **Simplified** — no fees, FileTransport demos, HTTP packaging split.  
19. **Strongest** — financial invariants + authority fencing + crash recovery.  
20. **Weakest** — product security + multi-container financial packaging.
