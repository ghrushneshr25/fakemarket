# P8.5 — Duplicate & Ordering Failure Recovery

**ADR:** 0053 · Builds on P8.1–P8.4

**Status:** 🟢 ACCEPTED (`32456f0`)

## Rule

> Duplicate or reordered input must never silently produce divergent authoritative financial state. Commands may be duplicated/delayed/reordered at the client boundary; WAL events remain uniquely identified and monotonically ordered; process-local idempotency is not durable exactly-once.

## Structural vs semantic duplicates

| Class | Identity | Enforcement |
|-------|----------|-------------|
| Structural | same EventID / Sequence | WAL reader + ApplyEvent envelope |
| Semantic | new EventID/Sequence, same OrderID/TradeID/reservation | Domain ApplyEvent (`ErrDuplicateOrder/Trade/Reservation`, lifecycle FSM) |

## Layers (not equivalent)

| Layer | Mechanism |
|-------|-----------|
| Command duplicate | Process-local `IdempotencyStore` (same key+fingerprint) or second order (no key) |
| Command order | Admission order into `InstrumentExecutor` (single-writer) → WAL |
| Event duplicate/gap/reorder | `wal.Reader` + recovery `ApplyEvent` fail-closed |

## Command delivery (test)

```go
of := chaos.NewOrderingFaults()
run := chaos.NewOrderingRunner(svc, of, wal.LastSequence)
run.Run(ctx, chaos.DeliveryPlan{
  Cmds: []chaos.PlannedCmd{ chaos.LimitBuy("S1", ...), chaos.CancelOf("C1","S1",...) },
  DeliveryOrder: []string{"C1","S1"}, // reorder
})
```

No second execution engine. Real `TradingService` only.

## Idempotency boundary

| Same process + same key + same FP | Cached result; no second WAL append |
| Same key + different FP | `ErrIdempotencyConflict` |
| No key | Distinct orders |
| After restart | **No** durable guarantee — Query, do not blind-retry |

Fingerprint: value-based (`FingerprintSubmit`); no pointer addresses.

## Event validation (fail-closed)

`ErrSequenceGap` · `ErrSequenceOutOfOrder` · `ErrSequenceDuplicate` · `ErrDuplicateEventID`  
Recovery: `ErrSequenceMismatch` · `ErrRecoveryCorruption` · Ready=false · no invented events
