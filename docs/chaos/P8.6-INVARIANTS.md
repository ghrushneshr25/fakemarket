# P8.6 — Financial Invariant Verification

**ADR:** 0054 · Package: `internal/invariants`  
**Status:** 🟢 ACCEPTED (`8d577df`)

## Rule

> No valid execution history may produce a financially inconsistent authoritative state, and no invalid history may be silently presented as financially valid.

## Verifier

```go
base := invariants.SnapshotBaseline(seedAccounts)
invariants.VerifyCanonical(c)              // structural snapshot checks
invariants.VerifyState(st)                 // State + executions
invariants.VerifyConservation(base, st)    // P12/P13 cash+position vs trades
invariants.VerifyStateWithBaseline(base, st)
```

**Financial oracle:** `DeriveExpected(baseline, state)` recomputes cash/positions from
`Initial + TradeExecuted settlement` using `MoneyFromPrice×qty` independently of final fields,
then `CompareExpectedToState`.

Read-only. Structured `Violation{Name, Entity, Expected, Actual, Context}`.

## ApplyEvent failure atomicity

- On error: `LastEventSequence` / `seenEventIDs` **not** advanced.
- Some apply paths (e.g. partial reservation) may mutate in-memory State before error.
- `StartupRecover` discards failed State → never Ready.
- Do not reuse State after failed ApplyEvent.
