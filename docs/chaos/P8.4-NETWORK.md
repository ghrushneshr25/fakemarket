# P8.4 — Network Failure & Transport Fault Recovery

**ADR:** 0052 · Builds on P8.1–P8.3 · Real `TradingService` + Query via bufconn gRPC

## Rule

> A transport failure may make the client uncertain, but it must never change or fabricate the authoritative financial outcome. WAL remains the source of truth.

## Injection

```go
nf := chaos.NewNetworkFaults()
nf.Arm(chaos.NetworkPlan{Kind: chaos.NetDropResponse, Occurrence: 1, Method: "SubmitOrder"})
st := chaos.StartNetworkStack(t, chaos.NetworkStackOpts{NF: nf})
// real TradingServer + QueryServer; interceptor at transport boundary only
```

Kinds: `DROP_REQUEST` · `DELAY_REQUEST` · `CANCEL_REQUEST` · `DROP_RESPONSE` ·
`DELAY_RESPONSE` · `PARTIAL_RESPONSE` · `CONNECTION_RESET` · `SERVER_CANCEL` ·
`CLIENT_DISCONNECT`

Occurrence is **1-based per kind+method**. Barriers supported for deterministic delay.

**Production:** do not register the interceptor; `NetworkFaults` nil = no-op.

## Unknown outcome (central)

```text
Submit → WAL durable → DROP_RESPONSE
Client: transport error / timeout  (NOT OrderRejected)
Server: order exists; Query/ListOrders/GetOrder reconcile
OracleFromWAL == StartupRecover
```

`timeout ≠ rejection`. `response loss ≠ rollback`.

## WAL × Response matrix

| WAL | Response | Expected |
|-----|----------|----------|
| FAIL | * | not acknowledged (`Append≠nil`); no success to client |
| SUCCESS | SUCCESS | authoritative + client certain |
| SUCCESS | FAIL | **authoritative + client uncertain** (P8.4 core) |

## Duplicate retry

Process-local idempotency only (P6 Option A). Same key + same fingerprint → cached result while process alive. Empty key → second order. **No durable cross-restart idempotency in P8.4.** After unknown outcome: **query, do not blind resubmit.**
