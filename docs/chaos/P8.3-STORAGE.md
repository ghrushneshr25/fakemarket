# P8.3 — Storage Failure

**ADR:** 0051 · Builds on P8.1/P8.2

## Rule

> Storage failure must never yield a successful durable acknowledgement (`Append==nil`) for an unsynced batch, and recovery must never invent state beyond the valid durable WAL prefix.

## Injection

```go
sf := chaos.NewStorageFaults()
sf.Arm(chaos.StoragePlan{Op: chaos.StorFailSync, Occurrence: 2})
wal.Open(wal.Config{Dir: dir, SyncOnAppend: true, OpenFile: sf.OpenFile})
```

Ops: `write` | `flush` | `sync` | `open` | `short_write` | `enospc`  
`AfterHeader: true` counts only after first successful Sync (segment header).

## Matrix (tests `TestP83_*`)

| Scenario | Result |
|----------|--------|
| Nil hooks | seq=1 durable + oracle |
| Write fail after header | no seq, faulted, ErrWALFaulted next |
| Sync fail occ=2 | no seq, faulted, recover 0 |
| ENOSPC | write fail, faulted |
| Open fail | Open error |
| Group commit sync fail | no seq |
| Short write | fail, no seq |
| Truncate tail | Strict not Ready |
| Checksum xor | reader error |
| Missing segment | ErrMissingSegment class |
| Rotation open fail | old durable recoverable |
| Runtime disappear | seq=1 kept |
| Trading-path Append fail | faulted writer |
