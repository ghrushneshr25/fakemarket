# P9.4 — Replication (CTO Q-bank)

> Implementation package: `internal/replication/`. ADR 0058.

**Q1. What is replicated?** Authoritative financial WAL events (`Event.Sequence` stream / CommandBatch + steps).  
**Q2. Why WAL not re-execute?** Re-execution would re-match and create duplicate financial facts. ApplyEvent folds facts only.  
**Q3. What is authoritative?** Primary WAL + primary matching/settlement.  
**Q4. What is a replica?** Deterministic fold of primary history; not an execution authority.  
**Q5. Can replica match?** No.  
**Q6. Can replica append independent financial events?** No.  
**Q7. What prevents second authority?** Role=REPLICA; Submit/AppendForbidden; no Promote API.  
**Q8. Role model?** Explicit PRIMARY vs REPLICA.  
**Q9. CURRENT?** Applied sequence caught up to known primary tip.  
**Q10. Received vs durable vs applied?** Distinct cursors; success ack = applied (+durable if local WAL).  
**Q11. Replication position?** Event.Sequence cursors on replica.  
**Q12. Why Event.Sequence?** Global ordered authoritative history key (P5).  
**Q13. Gaps?** Detected; replica FAILED; no skip.  
**Q14. Duplicates?** seq≤applied → no-op; no double apply.  
**Q15. Corruption?** WAL reader CRC/framing fail-closed; apply errors → FAILED.  
**Q16. Reorder?** Forbidden.  
**Q17. Apply twice?** No (duplicate gate + ApplyEvent EventID).  
**Q18. State reconstruction?** recovery.ApplyEvent from seed accounts/instruments.  
**Q19. Compare primary?** recovery.CompareCanonical fingerprints.  
**Q20. Fingerprint?** Canonical snapshot (orders, trades, accounts, res, book levels, seq).  
**Q21. Fingerprint data?** See recovery.Canonical fields.  
**Q22. Canonical order?** Sorted snaps in Snapshot().  
**Q23. Crash after durable before apply?** Restart folds local WAL; positions realign.  
**Q24. Crash after apply?** Restart resumes applied; catch-up continues.  
**Q25. Catch-up resume?** From LastApplied+1 via primary WAL stream.  
**Q26. Offline hour?** Lag grows; primary continues.  
**Q27. Primary keeps producing?** Yes; durable-before-ack unchanged.  
**Q28. Replica returns?** CatchUpFromWAL / hub ship.  
**Q29. Multiple replicas?** Independent Primary→A and Primary→B.  
**Q30. A→B?** Not in P9.4.  
**Q31. Why not?** Avoid multi-hop authority ambiguity.  
**Q32. Primary fails?** Replication stops; replica stays REPLICA.  
**Q33. Promote?** No.  
**Q34. Why not?** Failover is P9.5.  
**Q35. Ownership after primary failure?** Process-local ownership dies with primary; not auto-moved.  
**Q36. Deferred P9.5?** Failover / promotion.  
**Q37. Deferred P9.6?** Consensus / quorum.  
**Q38. P9.3 interaction?** Ownership not shipped as financial events; replica has no trading ownership.  
**Q39. Replica ownership token?** Not for trading authority.  
**Q40. Stale ownership execute on replica?** N/A — execute forbidden.  
**Q41. P8.6?** VerifyStateWithBaseline on replica State.  
**Q42. No duplicate trades?** Fingerprint + trade list equality after dups.  
**Q43. No double cash?** Conservation on replica.  
**Q44. Reservations?** Folded via reservation events; P8.6.  
**Q45. Sequence gap?** FAILED.  
**Q46. Later event first?** Gap fail.  
**Q47. Local WAL corrupt?** Reader/Open fails; reinit required.  
**Q48. Bottleneck?** Apply/fsync path (measured in bench catch-up).  
**Q49. Lag contract?** lag = primaryTip − applied (events).  
**Q50. Sync replication?** Would gate primary ack on replica durable — not P9.4 default.
