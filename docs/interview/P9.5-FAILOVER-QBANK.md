# P9.5 — Failover (CTO Q-bank)

**Q1. What is failover?** Controlled transfer of sole financial authority after primary unavailability.  
**Q2. Central invariant?** At most one node authorized for authoritative commands.  
**Q3. What fences old primary?** ClusterAuthority epoch + Fence; Validate rejects stale/fenced tokens.  
**Q4. Boolean primary=false enough?** No — must use token/epoch fencing.  
**Q5. Promotion order?** Fence old → new token → recover WAL → OpenResumed → Ready.  
**Q6. Why fence before new writes?** Prevent dual-writer window.  
**Q7. WAL sequence on promote?** Continues at LastApplied+1.  
**Q8. Reset sequences?** Forbidden.  
**Q9. Eligibility?** Healthy, durable==applied, P8.6, valid WAL.  
**Q10. Corrupt WAL promote?** Fail-closed; no PRIMARY.  
**Q11. Failure detector meaning?** Suspected unavailability, not death proof.  
**Q12. Detector alone promote?** No.  
**Q13. Replica selection?** Highest AppliedSequence, then NodeID lexical.  
**Q14. Two equal prefixes?** Deterministic NodeID order.  
**Q15. Stale command effect?** Zero financial mutation when gated.  
**Q16. Dual-writer test?** A rejected, B accepted.  
**Q17. Idempotent promote same node?** Returns current B token.  
**Q18. Promote C while B primary?** Requires explicit path; only one current.  
**Q19. Client ambiguous ack?** Reconcile via query; no auto-retry.  
**Q20. P9.5 solve consensus?** No — P9.6.  
**Q21. AuthorityToken fields?** Node, Epoch, Generation, WALSeq.  
**Q22. Generation role?** Registry lifetime bind.  
**Q23. P8.6 on promote?** Required before success.  
**Q24. Financial change on promote alone?** None.  
**Q25. Post-promote append?** seq N+1 on resumed writer.  
**Q26. TradeID continuity?** Recovered state + counters from history (writer path).  
**Q27. Multiple replicas?** One promoted; others remain non-authority.  
**Q28. Old primary WAL after promote?** Not authoritative.  
**Q29. Rematch on promote?** No.  
**Q30. Metrics?** failover_attempts, fence, duration — bounded labels.  
**Q31. OS-exit harness?** Recommended; unit/integration cover fencing (limitation if absent).  
**Q32. Split-brain claim?** Not claimed.  
**Q33. In-process authority limit?** Shared registry required for fence SoT.  
**Q34. Ready before recover?** Forbidden.  
**Q35. Failed promote fences old?** No — old remains until successful BeginPromote.
