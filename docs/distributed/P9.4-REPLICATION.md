# P9.4 — Replication

## Status

**IMPLEMENTED** (WAL shipping). Formal CTO 🟢 ACCEPTED pending external review.

## Goal

Replicate authoritative financial history to read-only replicas **without** a second
matching authority.

## Model

```
CLIENT → PRIMARY (match, risk, reserve, settle, WAL append)
              │
              ▼ durable Event.Sequence N
         Replication Hub (ship after primary durability)
              │
     ┌────────┴────────┐
     ▼                 ▼
  Replica A         Replica B
  (ApplyEvent)      (ApplyEvent)
  local WAL copy    local WAL copy
```

## Roles

| | PRIMARY | REPLICA |
|--|---------|---------|
| Execute trading | yes | **no** |
| Match / settle | yes | **no** |
| Append independent Event.Sequence | yes | **no** |
| Apply replicated events | n/a | yes |
| Auto-promote | n/a | **never in P9.4** |

## Replica lifecycle

`INITIALIZING → CATCHING_UP → CURRENT ⇄ LAGGING → FAILED`

**CURRENT** means `LastApplied >= PrimaryTip` (not merely process alive).

## Positions

| Cursor | Meaning |
|--------|---------|
| LastReceived | last accepted receive |
| LastDurable | last fsynced on replica-local WAL |
| LastApplied | last folded via `ApplyEvent` |

## ACK contract

`Replica.Receive` success ⇒ **APPLIED** (and **DURABLE** if local WAL configured).  
Duplicate `seq <= LastApplied` ⇒ success no-op.  
Gap / regression / apply error ⇒ **FAILED** (fail-closed).

Primary trading ack remains **primary WAL durable-before-ack only**.

## Catch-up / restart

- Empty: stream primary WAL 1..N
- Lagging: stream N+1..M
- Restart: fold local replica WAL → resume catch-up from applied+1

## State fingerprint

`recovery.State.Snapshot()` → `Canonical` compared with primary `RecoverDir` snapshot.

## Explicit non-goals

- Failover, consensus, Raft, quorum, distributed ownership, auto-promotion
- Replica-to-replica chaining
- Changing P1–P8 trading semantics
