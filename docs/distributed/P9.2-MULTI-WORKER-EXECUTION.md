# P9.2 — Multi-Worker Execution

**ADR:** 0056 · Code: `trading/worker.go`, `bootstrap.go`  
**Builds on:** P9.1 instrument sharding

## Principle

Multiple workers increase concurrency across instruments without creating a second authority for any InstrumentID or weakening WAL/financial contracts.

## Ownership chain

```text
InstrumentID ──FNV-1a % Nshards──► ShardID ──% Nworkers──► WorkerID
                                                              │
                                                    instrumentRunner (FIFO)
                                                              │
                                                    InstrumentExecutor.x.mu
```

## Scheduling

- Per-instrument bounded channel (default cap 256).
- One goroutine per instrument drains FIFO → executor.Submit/Cancel.
- Same worker, different instruments: concurrent runners.
- Same instrument blocked: only that runner blocked; others proceed.
- Queue full → `ErrBackpressure` (reject, not drop).

## Lifecycle

```text
CREATED → STARTING → RUNNING → DRAINING → STOPPED
```

`BootstrapResult.Shutdown()`: not-ready → pool.Stop (drain) → WAL.Close.

## WAL

Shared process WAL; durable-before-ack; global Event.Sequence; global TradeIDs (P9.1).

## Recovery

Rebuild topology with same NumShards/NumWorkers → deterministic owners after Attach+Start; Ready only after init.

## Non-goals

Replication · failover · migration · consensus · remote RPC · multi-process ownership
