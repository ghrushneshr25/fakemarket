# P9.6 — Consensus / Split-Brain Prevention

## Status

**IMPLEMENTED** (Raft-style quorum authority). Formal CTO 🟢 ACCEPTED pending review.

## Core question

> Can two partitioned nodes both pass the authoritative command gate and mutate financial state?

**Required answer: NO.**

## Model

```
Consensus Group {A,B,C}
        quorum = 2
             │
    exactly one LEADER (or zero if no quorum)
             │
             ▼
    TradingService.AuthorityGate (consensus.Node)
             │
             ▼
    Financial WAL (Event.Sequence)
```

## Roles

`FOLLOWER` → (timeout) → `CANDIDATE` → (quorum votes) → `LEADER`

## Quorum

`floor(N/2)+1` — minority partition cannot elect.

## Durable state

`DataDir/<node>/consensus-meta.json`: `currentTerm`, `votedFor` (fsync).

## Authority gate

`Node.AuthorizeCommand()` succeeds **only** if `IsLeader()`.

Wired via existing P9.5 `TradingService.WithAuthority`.

## Safety vs liveness

| | |
|--|--|
| **Safety** | Never two authoritative writers |
| **Liveness** | Elect leader when quorum reachable |
| Total partition | Zero leaders OK |

## Partition tests

- 3-node elect one
- Isolate leader; majority elects; heal → one writer
- Total partition → zero writers
- Stale leader Submit via real TradingService → reject, zero mutation

## Explicit non-goals

Full Raft financial log, BFT, K8s, external DB, P10.
