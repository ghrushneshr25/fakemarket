# P9.1 — Instrument Sharding

**ADR:** 0055 · Code: `internal/application/trading/shard.go`, `router.go`, `bootstrap.go`  
**Status:** 🟢 ACCEPTED (`22ce296`)

## Principle

> Every instrument has exactly one authoritative execution owner; commands for that instrument are serialized by that owner; independent instruments execute concurrently without changing financial semantics.

## Model

```text
InstrumentID ──FNV-1a % N──► ShardID ──► Shard ──► InstrumentExecutor ──► OrderBook
                                                              (1:1)
```

- **Shard** = ownership/routing unit (future P9.2 transfer unit).
- **Executor** = matching single-writer (unchanged).
- **WAL** = process-global shared stream + monotonic Event.Sequence.

## Algorithm

```text
h = FNV-1a-32(UTF-8 InstrumentID string)
ShardID = h % NumShards   // NumShards >= 1
```

Deterministic across processes. Independent of pointers/scheduling.

## Configuration

```go
trading.BootstrapSharded(walDir, numShards, accounts, instruments...)
// or BootstrapCfg{NumShards: N, ...}
```

`NumShards <= 0` → error.

## Ownership invariant

`Topology.OwnerOracle()`:

- each registered instrument appears on exactly one shard
- executor identity matches instrument
- no shared executor across instruments

## WAL note

```text
shard execution order ≠ global Event.Sequence order
```

Concurrent shards may interleave journal sequences. Per-instrument history remains executor-serialized.

## Recovery

- Financial state: existing `StartupRecover` (WAL fold).
- Topology: rebuild with same or different `NumShards`; assignment recalculated from InstrumentID.
- Never two owners for one instrument.

## Shared account concurrency (P9.1)

```text
ReservationStore.mu  — atomic Reserve / AvailableCash (no over-reservation)
AccountRegistry.WLock — settle Debit/Credit/positions (no lost cash updates)
InstrumentExecutor.x.mu — matching only (not shared across instruments)
```

Same account on two shards: concurrent Reserve is fail-closed on capacity;
settlement serializes under account write lock. No global account mutex.

Process-global `CounterIDs` shared across engines so TradeID is unique in WAL.
