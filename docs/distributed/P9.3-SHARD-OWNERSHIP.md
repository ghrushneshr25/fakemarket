# P9.3 — Shard Ownership

## Status

**IMPLEMENTED** (in-process). Formal CTO 🟢 ACCEPTED pending external review.

## Goal

Make shard ownership an **explicit control-plane authority** with OwnerID, epoch,
lifecycle states, and fencing before financial mutation — without failover,
replication, or consensus.

## Ownership chain

```
InstrumentID → ShardID (FNV-1a % N)
            → OwnershipRegistry.Acquire → OwnerID + Epoch
            → WorkerID (OwnerFromWorker)
            → instrumentRunner (FIFO)
            → Validate(token)  // fence
            → InstrumentExecutor → match → shared WAL
```

## Types

| Type | Role |
|------|------|
| `OwnerID` | Control-plane identity (`worker-N`) |
| `OwnershipToken` | `{Shard, Owner, Epoch, Generation}` authorization context |
| `ShardOwnership` | Authoritative record + `OwnershipState` |
| `OwnershipRegistry` | Acquire / Release / Validate |

### States

`UNOWNED → ACQUIRING → OWNED → RELEASING → UNOWNED`

### Epoch + Generation

- Global monotonic **Epoch** bumped on every **successful first acquire**.
- Same-owner re-acquire is idempotent (returns current token, no bump).
- **Generation** is unique per registry/process lifetime; prior-process tokens fail Validate.
- Stale epoch/generation → `ErrStaleOwnership` / `ErrNotOwner`.
- Ownership is **not** written to the financial WAL; reconstructed at Attach.

## Lifecycle

### Startup

1. Build topology + workers.
2. `EnsureShard` for all shards.
3. `Acquire` exclusive ownership per worker.
4. Attach instruments; store tokens on workers.
5. Start workers → Ready.

### Runtime fencing

- Enqueue path: `validateShard` before queue accept.
- Exec path: `validateShard` again immediately before `InstrumentExecutor.Submit/Cancel`.
- Rejected commands produce explicit errors; no book/res/account/WAL financial write.

### Shutdown

1. Stop admission (`SetReady(false)`).
2. Drain per-instrument queues.
3. `ReleaseAllByOwner` for every worker.
4. Clear tokens; close WAL.

## Errors

| Error | Meaning |
|-------|---------|
| `ErrNotOwner` | Token owner ≠ current owner or not OWNED |
| `ErrStaleOwnership` | Epoch mismatch |
| `ErrAlreadyOwned` | Concurrent/duplicate acquire by other owner |
| `ErrOwnershipEpochMismatch` | Release with wrong epoch |
| `ErrOwnershipInvalidState` | Illegal lifecycle transition |

## Out of scope (later)

- Multi-process ownership, Raft/etcd, failover, live migration, remote RPC,
  client-controlled ownership, wall-clock leases.
